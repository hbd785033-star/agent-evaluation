# Agent 评估 Skill

## 触发条件

执行 Agent 完成任何任务后，立即运行此 Skill 进行评估。

## 评估流程

### 第一步：读取任务目标和验收条件

从任务描述或 YAML 测试案例中读取：
- `success_criteria.deterministic`：程序化检查项
- `success_criteria.llm_judge`：主观质量检查项
- `limits`：Agent、工具调用、成本上限

**不根据执行 Agent 的自我陈述判定成功。**

### 第二步：确定性检查（必须先跑）

按序执行：
1. 测试是否通过（运行 pytest 或对应测试命令）
2. Outcome 验证：检查环境最终状态（文件、数据库、API 端点），不只检查对话文本
3. 检查 Git Diff——是否修改了 forbidden_files
4. 格式/lint/类型检查
5. URL 可访问性（研究任务）
6. API Key 泄漏检查

### 第三步：执行轨迹评估

检查工具调用记录：
- 是否调用了禁止工具
- 是否反复读取相同文件（>3次为异常）
- 是否连续失败后重复重试相同操作
- 子 Agent 数量是否超限

### 第四步：效率/成本评估

检查：
- 总 Token 消耗和缓存命中率
- 工具调用次数
- 估算成本是否超出 `limits.max_cost_usd`
- 重试次数

### 第五步：主观质量评分（LLM Judge）

仅在前四步通过后执行。
返回结构化 JSON：

```json
{
  "passed": false,
  "score": 72,
  "failures": ["<具体失败原因，附证据>"],
  "evidence": ["<支持判断的证据>"],
  "retry_instruction": "<最小修复指令>"
}
```

## 返工规则

- **不合格时**：输出 `retry_instruction`，最多允许执行 Agent 返工一次
- **返工后仍不合格**：标记为 FAIL，不再重试，上报人工审核
- **不得自行降低验收标准**
- **不得接受"基本完成"作为通过依据**

## 评分基线

| 分数 | 含义 |
|------|------|
| 90-100 | 优秀，无需任何修改 |
| 80-89 | 合格，可接受 |
| 60-79 | 有问题，建议返工 |
| <60 | 不合格，必须返工 |

## 禁止行为

- 不根据对话文本"看起来完成了"就判为通过
- 不在未检查测试结果时评 >80 分
- 不接受超出 `allowed_files` 范围的修改
- 不忽略成本超支问题
